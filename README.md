# Mission Tycoon

**A cozy 3D space-agency builder where every number on screen is a real mission-design trade-off.**
Built for the 2026 NASA Space Apps Challenge, challenge **"Space Mission Design Game."**

**Play it:** https://userbiznes.github.io/mission-tycoon/ (desktop, or a phone held sideways)

You run a small, run-down space agency on an old coastal spaceport. A grumpy-but-kind instructor,
Chief Rocco, shows you around. You buy and order parts at the market, build satellites in the
Integration Bay, launch them from a rusty pad, and fly missions for clients. Satellites in orbit keep
sending raw data to your dish; your Science Lab turns raw photos into maps that clients pay for.
It looks like a farm-builder, but the game is the mission design: mass, power, budget, data,
communications and time, and a debrief that always tells you **why** the mission went the way it did.

## How to play

1. **Start**, name yourself and your agency, and design a logo (it goes on the HQ flag and every rocket).
2. Follow **Chief Rocco's tour**: buy a camera, order a battery, watch the truck bring it.
3. Take the **First Light** contract at Mission Control.
4. In the **Integration Bay**, tap or drag parts onto the satellite. Watch the six bars. Tap any bar for **Why?**
5. Press **Test run** (free) to see the predicted stars and the reasons, then fix the design.
6. **To the pad**: pick orbit, rocket and ground stations, read the GO / NO-GO poll, launch.
7. Fly the launch yourself (hold to fire, drop the stage, burn at the top) or switch on **Autopilot**.
8. Watch **operations**: the data pipeline strip shows the slowest link in red; swipe the decision cards.
9. Read the **debrief**: 0–3 stars, the top three reasons, the money, the closest real NASA mission.
   **Fix and relaunch**, or go back to base.
10. Build the **Science Lab**, turn raw data into products, fill small orders, upgrade, hire crew.

Settings (gear icon): **Fast mode** (all timers ×4 faster, for judges), Low quality, Sound, Reset game.
URL flags: `?fast=1`, `?low=1`, `?fresh=1` (clean save without touching storage).

## How the challenge objectives map to the game

| Challenge asks for | Where it is in the game |
| --- | --- |
| Define a mission objective | Mission Control contract board: client, target region, science target, deadline, fee |
| Design a spacecraft | Integration Bay builder: bus plus parts on a 3D turntable, slot limits |
| Choose instruments | Instruments stall: wide camera, high-res camera, thermal sensor; parts the client can't use are locked with the reason |
| Choose a launch vehicle and orbit | Launch prep: rideshare, small and medium rockets; low, mid and polar orbits; mass vs capacity gauge |
| Manage mass, power, budget, data, communications, time | The six resource bars, live, each with a one-line reason when red and a "Why?" explanation |
| Simulate the mission | Free test run, launch cinematic, day-by-day operations time-lapse with a data pipeline strip |
| Show **why** it succeeded or failed | Debrief: top three reasons in plain sentences, generated by the rules engine, plus what would fix it |
| Change the design and try again | "Fix and relaunch" returns to the builder with the same satellite |
| Roles (optional) | Four crew seats (Science, Spacecraft, Launch, Ground), each calling GO / NO-GO with a reason |
| Scoring, difficulty, scenarios | Three stars per mission, XP and agency levels, a campaign of contracts of rising difficulty |
| Random events | Swipe decision cards (solar storm, rain at the station, cold battery, wildfire, wobbly wheel) with previewed effects |
| Dashboard and reports | Resource bars, pipeline strip, payout breakdown, closest real NASA mission |

## The real-world basis for each rule

The numbers are game values, but each rule is a simplified real one. The rules engine is pure TypeScript
in `src/sim` with 56 unit tests (`npm test`); all balancing lives in typed tables in `src/data`.

- **Mass:** total mass must fit the rocket's capacity for that orbit. Reaching low Earth orbit takes about
  9.4 km/s of delta-v, so every kilogram costs rocket. Higher orbits take more, so the same rocket lifts less there.
- **Power in sunlight:** solar output must be at least 1.6 × the average load. A low orbit takes about
  95 minutes, with about 60 in sunlight and 35 in Earth's shadow (95 / 60 ≈ 1.6). Sunlight at Earth carries about 1,361 W/m².
- **Power in shadow:** the battery must carry the satellite through about 35 minutes of darkness every orbit
  (0.6 Wh per watt of load). Draining a small battery deep on every orbit wears it out, which shortens orbital life.
- **Budget:** parts, launch, ground stations and salaries come out of the bank. The game warns below a 10% reserve;
  NASA's CubeSat 101 advises teams to hold reserves for surprises.
- **Data:** what reaches the ground each day is the **minimum** of what the instruments make, what the computer can
  hold, and what the passes can carry. Overflow is lost. This is the "slowest link" lesson.
- **Communications:** passes per day depend on where the ground station is and on the orbit (a polar orbit passes
  a polar station on almost every lap). Faster radios use narrow beams and need fine pointing.
- **Time:** parts add build months against the contract deadline; the orbit sets how long the satellite lasts
  (thin air at 400 km drags a satellite down in about a year).
- **Launch:** the readout shows real figures on a compressed timeline: the 100 km edge of space, and the
  orbital speed for the chosen altitude, v = √(GM / r) (about 7.7 km/s at 400 km).
- **Science Lab:** products follow NASA's data processing levels: raw Level 0 → calibrated Level 1 → mapped Level 3.

## NASA resources used

- **CubeSat 101: Basic Concepts and Processes for First-Time CubeSat Developers** (NASA CubeSat Launch Initiative): bus sizes, subsystems, schedule and reserves.
- **NASA's total solar irradiance figure** (about 1,361 W/m²): the sunlight power rule.
- **NASA Earthdata: Data Processing Levels**: the Science Lab production chain.
- **Build It Yourself: Satellite!** (NASA): inspiration for instrument and trade-off choices.
- **Design and Develop Science Missions** (NASA Science): the mission life cycle the contract flow follows.
- Real missions named in the debrief (for example the HARP CubeSat, Landsat 9, Lunar Reconnaissance Orbiter) are described in one plain sentence each.

No NASA imagery is used. The mission globe is drawn procedurally in code. No NASA logos, mission patches or branding appear anywhere.

## Run it

```bash
npm install
npm run dev     # http://localhost:5173
npm test        # rules-engine unit tests
npm run build   # production build in dist/
```

Stack: Vite, TypeScript, React, react-three-fiber, zustand, vitest. No backend; the save lives in localStorage.
Every push to `main` builds, tests and deploys to GitHub Pages (`.github/workflows/deploy.yml`).

## Project layout

```
src/art     palette, procedural modelling kit, model registry, every 3D model, the agency logo
src/scene   world, water, sky, lighting, camera rig, launch cinematic, delivery truck
src/data    typed tables: parts, orbits, rockets, stations, contracts, events, crew, lab, economy, tutorial
src/sim     the rules engine (pure TypeScript) and its tests
src/state   saved game, mission flow, economy loop, launch state, settings
src/ui      HUD, sheets, builder, launch prep, launch overlay, operations, debrief, Chief Rocco
```

## Use of AI

This game was built with **Claude Code** (Anthropic), directed by the team: the code, the procedural 3D
models, the rules engine and the in-game text were written with AI assistance and reviewed through
screenshots and tests. There are **no AI-generated images or video** in the game; every model is geometry
built in code and every icon is hand-written SVG.
